# AI 一角焕新：视觉搜索大赛初步方案

> 版本：V0.1
> 核心口号：把抖音里的家居灵感，搬进我的家。

## 1. 项目概述

### 1.1 一句话定位

面向年轻租房与家居兴趣用户的 AI 空间适配助手：用户圈选抖音中的家居灵感，再拍摄自己的真实空间，AI 在预算、尺寸和改造限制内生成可预览、可购买、可执行的一角焕新方案。

### 1.2 核心价值

- 将“刷到喜欢”转化为“适合我家”，解决灵感难落地的问题。
- 将视觉搜索从识别单品升级为理解空间、偏好与约束，并辅助决策。
- 以真实商品和教程承接效果方案，打通内容种草、方案生成、购买与改造。
- 持续沉淀用户的空间档案和审美偏好，形成长期复用价值。

### 1.3 项目边界

比赛阶段聚焦“一角焕新”，优先完成书桌区域改造，不做整屋硬装设计，不承诺厘米级测量，也不处理承重、管线等专业施工问题。

## 2. 产品方案

### 2.1 产品定位

AI 一角焕新不是缩小版家装设计软件，而是抖音内容生态中的“家居灵感转化器”：

```text
内容激发 → 灵感理解 → 空间适配 → 效果预览 → 商品与教程承接 → 改造分享
```

### 2.2 目标用户

| 用户 | 典型特征 | 核心诉求 |
| --- | --- | --- |
| 年轻租房用户 | 预算有限、不便硬装 | 低成本、免打孔、可恢复改造 |
| 学生及年轻白领 | 高频使用书桌，重视效率与氛围 | 桌搭、收纳、照明和数码配件 |
| 家居内容兴趣用户 | 收藏多、行动少 | 将喜欢的风格迁移到真实空间 |
| 初次布置住所用户 | 缺少设计经验 | 快速获得成套、可信的购买方案 |

### 2.3 核心需求场景

#### 场景 A：从抖音内容出发

用户刷到喜欢的桌搭视频，暂停并圈选台灯、置物架或整体风格，点击“搬进我家”；随后选择已有空间档案或拍摄书桌，AI 生成适配方案。

#### 场景 B：从真实空间出发

用户拍摄书桌并提出要求，例如：“桌面太乱，预算 500 元，不能打孔。”AI 诊断问题，结合历史灵感生成方案和购物清单。

#### 场景 C：长期灵感资产

用户收藏家居视频后，系统自动提取空间类型、颜色、材质、风格和单品，形成审美档案。后续改造时直接调用，不要求用户手工整理。

### 2.4 核心用户路径

1. **触发：** 圈选抖音视频中的灵感，或直接拍摄真实空间。
2. **补充约束：** 选择预算、是否打孔、保留物品，并提供一个参考尺寸。
3. **AI 理解：** 分析空间问题、灵感元素和用户偏好。
4. **方案规划：** 基于真实商品生成 2～3 套可落地方案。
5. **效果预览：** 保留原有结构，对指定区域进行局部编辑。
6. **行动承接：** 查看商品、达人教程、摆放步骤与预算明细。
7. **持续互动：** 调整预算或风格、替换单品、保存方案并分享前后对比。

### 2.5 功能模块

| 模块 | 核心能力 | MVP 优先级 |
| --- | --- | --- |
| 灵感圈选 | 识别视频画面中的单品与设计语言 | P0 |
| 空间拍摄与标定 | 上传图片，填写桌宽等参考尺寸 | P0 |
| 空间诊断 | 识别空间、已有物品、问题与可编辑区域 | P0 |
| 约束采集 | 预算、租房限制、保留物品、风格偏好 | P0 |
| 方案生成 | 生成 2～3 套布局与搭配方案 | P0 |
| 局部效果图 | 保持墙体、门窗和主要家具不变 | P0 |
| 商品与教程 | 真实商品清单、改造视频和操作步骤 | P0 |
| 灵感与空间档案 | 自动归类收藏，记录偏好与方案 | P1 |
| 方案分享 | 生成改造前后对比卡或短视频模板 | P1 |

### 2.6 AI 卡片输出

每次结果采用结构化卡片，不输出大段泛化建议：

1. **空间诊断：** 当前问题、可利用区域和判断依据。
2. **方案预览：** 2～3 套效果图，展示预算与风格差异。
3. **适配说明：** 保留了什么、改变了什么、为什么适合。
4. **执行清单：** 商品、尺寸建议、摆放位置、价格和安装难度。
5. **内容承接：** 达人教程、商品测评和相似真实案例。
6. **继续操作：** 换风格、降预算、替换单品、查看步骤或保存方案。

### 2.7 抖音生态优势

- **需求激发：** 家居、桌搭、收纳等短视频天然激发改造需求。
- **视觉入口：** 暂停圈选即可保存灵感，降低描述风格和单品的门槛。
- **内容供给：** 达人教程、真实案例、评论经验和商品测评可共同支撑决策。
- **兴趣理解：** 结合收藏和消费行为，逐步形成个人审美档案。
- **交易承接：** 从真实商品出发生成效果图，缩短种草到购买的路径。
- **内容回流：** 用户可分享改造前后对比，形成新的内容与需求。

### 2.8 增长与 ROI

#### 冷启动

- 在桌搭、租房改造、收纳视频中投放“试试搬进我家”入口。
- 联动家居达人制作同一空间、不同预算的改造案例。
- 以“300 元焕新书桌”等明确主题降低首次体验门槛。

#### 留存

- 保存空间档案，支持后续局部迭代和新增单品试摆。
- 自动更新审美档案，按季节、预算和使用目标推荐方案。
- 改造后邀请用户拍照复查，生成二次优化建议。

#### 收益与成本

- 收益来源：商品点击与成交、内容消费增长、品牌联合方案。
- 成本控制：先完成轻量诊断，确认意向后再生成效果图；复用空间特征和缓存结果；限制单次候选方案数量。

## 3. 技术方案

### 3.1 总体架构

```mermaid
flowchart LR
    A["输入层<br/>抖音画面、空间照片、语音或文本"] --> B["理解层<br/>灵感解析、空间诊断、约束提取"]
    B --> C["规划层<br/>空间适配 Agent"]
    C --> D["检索层<br/>商品、教程、案例"]
    D --> E["生成层<br/>局部效果图与结构化方案"]
    E --> F["校验层<br/>结构、预算、商品、风险检查"]
    F --> G["输出层<br/>AI 卡片、追问、保存与分享"]
    G --> H["记忆层<br/>空间档案与审美偏好"]
    H --> C
```

### 3.2 Agent / Skill 模块

| Skill | 输入 | 输出 |
| --- | --- | --- |
| `extract_inspiration_style` | 圈选画面、视频上下文 | 风格、颜色、材质、核心单品 |
| `extract_room_constraints` | 空间照片、标定信息 | 空间类型、已有物品、可编辑区 |
| `build_user_constraints` | 文本或语音、历史偏好 | 预算、限制、保留项和目标 |
| `retrieve_products` | 方案需求与尺寸范围 | 可购买商品候选及属性 |
| `retrieve_douyin_content` | 风格、问题与任务 | 教程、测评和真实案例 |
| `generate_design_plan` | 空间、灵感、约束、商品 | 结构化布局与搭配方案 |
| `render_room_edit` | 原图、编辑蒙版、商品图 | 保持结构的局部效果图 |
| `validate_design_plan` | 方案、效果图、商品数据 | 预算、尺寸、结构和一致性报告 |
| `compose_ai_card` | 校验后的全部结果 | 前端可渲染的结构化卡片 |

### 3.3 模型与工具链

- **多模态模型：** 解析空间、物品、风格、颜色与用户指令。
- **大语言模型：** 任务规划、方案解释、追问生成和结果编排。
- **图像编辑模型：** 基于原图、蒙版与商品参考图完成局部重绘。
- **检测与分割模型：** 标记桌面、墙面、家具和可编辑区域。
- **向量检索：** 检索相似风格、用户历史灵感、教程和案例。
- **商品与内容接口：** 获取价格、尺寸、库存、商品图和视频元数据；比赛阶段可用样例库模拟。
- **前端：** H5 优先，完成上传、圈选、约束选择、方案切换与卡片交互。
- **后端编排：** 以 Workflow 串联 Skills，保存中间结果、日志和失败降级信息。

### 3.4 数据流

```text
原始输入
→ 视觉特征与结构化标签
→ 用户约束补全
→ 商品、教程和案例召回
→ 多方案规划与排序
→ 局部效果图生成
→ 一致性与风险校验
→ AI 卡片 JSON
→ 用户反馈写入空间档案与审美记忆
```

建议统一核心数据对象：`InspirationProfile`、`RoomProfile`、`UserConstraints`、`ProductCandidate`、`DesignPlan`、`ValidationReport` 和 `AICard`，方便前后端并行开发。

### 3.5 关键难点与风险控制

| 风险 | 影响 | 控制方案 |
| --- | --- | --- |
| 生成图改变墙体或家具 | 效果惊艳但不可信 | 使用区域蒙版；锁定结构；生成前后做视觉一致性检查 |
| 单张照片缺少真实尺度 | 商品可能放不下 | 要求一个参考尺寸；使用尺寸区间；标注“建议复测” |
| 效果图与商品不一致 | 无法购买和复现 | 先检索真实商品，再以商品图驱动生成 |
| 方案超预算或不符合限制 | 结果不可执行 | 规划前注入硬约束，输出前再次校验 |
| 模型识别不确定 | 错误建议降低信任 | 展示置信度；关键信息不足时追问或要求补拍 |
| 生成延迟与成本偏高 | 影响体验与 ROI | 先输出诊断和草案；按需生成高清图；缓存空间特征 |
| 专业施工与安全风险 | 可能误导用户 | MVP 仅做软装；涉及用电、承重、消防时提示咨询专业人员 |
| 用户空间照片隐私 | 降低使用意愿 | 明示用途；最小化保存；提供删除入口；敏感画面脱敏 |

## 4. 比赛实现方案

### 4.1 MVP 范围

**主场景：** 书桌区域一角焕新。
**核心案例：** 用户圈选抖音原木风桌搭，上传自己的书桌照片，填写“预算 500 元、不能打孔、保留桌椅”，获得 2～3 套可执行方案。

MVP 必须完成：

- 1 个灵感视频或关键帧的圈选与解析；
- 1 张书桌照片上传及参考尺寸输入；
- 预算、打孔限制、保留物品等约束采集；
- 空间诊断和 2～3 套结构化方案；
- 至少 1 套局部效果图；
- 基于样例商品库的清单、预算和尺寸建议；
- 相关教程卡片与继续追问；
- 核心流程封装为可调用 Agent / Skill。

MVP 暂不实现：整屋建模、精准测量、硬装施工、全量真实商品接入、实时视频连续理解。

### 4.2 最终交付物

1. **项目文档：** 用户问题、产品方案、技术架构、增长策略、指标、风险和路线图。
2. **H5 / 小程序原型：** 可完整演示“圈选灵感—上传空间—生成方案—查看商品与教程”。
3. **可调用 Skill / Agent：** 接收标准输入并返回 `AICard` JSON，至少跑通理解、规划、检索、生成和校验。
4. **演示素材包：** 标准输入、生成结果、异常兜底案例和演示视频。

### 4.3 模块化开发流程

| 阶段 | 工作内容 | 主要产出 |
| --- | --- | --- |
| 1. 场景与数据定义 | 固定书桌案例、输入约束和卡片结构 | 用户故事、Schema、验收样例 |
| 2. 原型与样例库 | 完成交互原型，整理商品与教程样例 | 可点击原型、样例数据库 |
| 3. 视觉理解 | 灵感解析、空间诊断、区域标记 | 结构化识别结果 |
| 4. Agent 编排 | 方案规划、检索、排序和追问 | 可调用 Workflow |
| 5. 效果图生成 | 商品驱动局部编辑、结构保持 | 方案效果图 |
| 6. 校验与降级 | 预算、尺寸、结构、缺失数据检查 | 校验报告、兜底路径 |
| 7. 前后端集成 | 串联完整用户路径 | 可体验 H5 / 小程序 |
| 8. 测试与演示 | 固定主案例，覆盖异常情况 | 最终 Demo、演示稿 |

### 4.4 团队分工建议

| 角色 | 主要职责 |
| --- | --- |
| 产品与项目统筹 | 场景收敛、需求文档、指标、进度和答辩 |
| AI / Agent 工程 | Prompt、Workflow、检索、校验与接口 |
| 视觉生成工程 | 分割、局部重绘、商品一致性和效果优化 |
| 前后端工程 | H5 / 小程序、服务编排、数据与日志 |
| 设计与内容运营 | 交互视觉、样例素材、达人内容与增长方案 |

人员较少时，可合并产品与设计、Agent 与后端两个角色。

### 4.5 阶段里程碑

| 里程碑 | 验收标准 |
| --- | --- |
| M1：方案冻结 | 用户路径、MVP、Schema 和主案例确定 |
| M2：单模块可用 | 空间与灵感均能输出稳定结构化结果 |
| M3：主链路跑通 | 输入到 AI 卡片全流程可调用 |
| M4：效果可信 | 原空间结构基本保持，商品与清单一致 |
| M5：体验可演示 | H5 / 小程序可连续完成主案例 |
| M6：交付完成 | 文档、原型、Agent、视频和答辩材料齐备 |

### 4.6 三分钟演示脚本

1. **0:00～0:25｜需求激发：** 用户在抖音刷到原木风桌搭，圈选画面并点击“搬进我家”。
2. **0:25～0:50｜真实空间：** 上传杂乱书桌照片，填写桌宽 1.2 米、预算 500 元、不能打孔、保留桌椅。
3. **0:50～1:20｜AI 理解：** 展示灵感提取与空间诊断，说明不能原样照搬的原因。
4. **1:20～2:05｜方案生成：** 展示 3 套方案，重点打开一套效果图并对比改造前后。
5. **2:05～2:35｜任务闭环：** 展示真实商品清单、预算、摆放步骤和达人教程。
6. **2:35～2:50｜连续交互：** 输入“压到 300 元以内”，实时替换商品并更新方案。
7. **2:50～3:00｜生态飞轮：** 保存空间和审美档案，生成分享卡，回到抖音内容消费与传播。

### 4.7 评审维度对齐

| 评审维度 | 方案回应 |
| --- | --- |
| 真实场景成立（20%） | 收藏灵感难落地、局部空间难搭配，书桌改造高感知且低门槛 |
| 多模态必要性（20%） | 风格、现有物品、空间关系和可编辑区域难以用文字准确描述 |
| 抖音生态放大（20%） | 圈选内容激发需求，达人教程与商品承接，改造结果再次形成内容 |
| AI 链路可落地（25%） | 理解、规划、检索、生成、校验和卡片输出均拆成可调用 Skill |
| 增长与 ROI（15%） | 场景化入口冷启动，空间与审美档案促留存，商品转化与内容增长形成收益 |

## 5. 关键指标

### 5.1 北极星指标

**有效焕新方案完成数：** 用户生成方案后，至少完成保存、继续调整、查看教程或点击商品中的一项有效行动。

### 5.2 分层指标

| 环节 | 指标 |
| --- | --- |
| 入口 | 圈选入口点击率、拍摄或上传完成率 |
| 理解 | 灵感与空间识别准确率、补充追问率 |
| 生成 | 方案生成成功率、首图时延、单次任务成本 |
| 满足 | 方案收藏率、继续调整率、主观满意度 |
| 承接 | 教程播放率、商品点击率、加购或成交转化率 |
| 留存 | 空间档案建立率、7 日复用率、二次焕新率 |
| 传播 | 前后对比分享率、分享内容播放与互动率 |
| 安全与可信 | 结构误改率、超预算率、商品不一致率、隐私投诉率 |

## 6. 后续扩展

1. **空间扩展：** 从书桌延伸到床头、玄关、阳台、空墙和沙发角。
2. **能力扩展：** 从单图升级为短视频扫描、空间标定和多角度一致生成。
3. **资产扩展：** 建立多房间档案、家庭成员偏好和已有物品库。
4. **场景扩展：** 支持节日布置、搬家、儿童成长、宠物友好和季节焕新。
5. **生态扩展：** 接入更多真实商品、达人服务、品牌专题与本地安装服务。
6. **闭环扩展：** 用户上传改造结果，AI 对比方案与实景并给出复盘优化建议。

## 7. 团队当前决策建议

- 以“书桌区域一角焕新”作为唯一主 Demo，其他空间只展示扩展性。
- 坚持“先选真实商品，再生成效果图”，保证方案可购买、可复现。
- 优先打磨结构保持、预算约束和商品一致性，避免只追求视觉冲击。
- 用一个成功主案例和一个信息不足的追问案例，证明 Agent 主链路与风险控制均可落地。

## 8. MVP 实现补充

### 8.1 当前成熟度与演示边界

第一版定义为“运行时静态、交互可演示”的比赛 MVP：前端能完整跑通主链路，但视觉识别、内容召回、商品库存和效果图生成使用样例数据或预生成素材。界面必须显式标记样例数据，不能把模拟结果描述成真实线上能力。

### 8.2 对象模型与所有权

- `RoomProfile`：一个稳定的真实空间身份，拥有尺寸假设、固定结构、已有家具和风险信息。
- `InspirationProfile`：一次灵感提取结果，可独立替换，不直接修改空间档案。
- `UserConstraints`：当前任务的预算、硬限制、保留项和目标；默认只作用于本次方案。
- `DesignPlan`：可版本化的方案快照，拥有商品、摆放、预算、步骤和效果图。
- `ValidationReport`：针对某个方案版本的校验结果，不与方案文案混写。
- `AICard`：面向前端展示的组合视图，不作为底层事实来源。

### 8.3 必须覆盖的状态

```text
empty
→ inspiration_selected
→ room_ready
→ constraints_ready
→ analyzing
→ needs_clarification | result_ready | degraded
→ adjusting
→ saved | discarded
```

MVP 至少演示正常生成、预算调整和识别信息不足三类状态。保存的是结构化方案与空间档案，不保存一次性的加载状态；用户取消或刷新时，未保存的本地图片应被清除。

### 8.4 数据来源与可信声明

- 所有商品必须带 `source_type`、价格更新时间、尺寸区间、安装方式和库存状态。
- 所有内容卡片必须保留内容 ID、作者、来源和跳转信息。
- 预生成效果图标记为 AI 示意；布局和商品清单才是执行依据。
- 图像识别中的估算字段必须带置信度与 `needs_confirmation`。
- 比赛样例数据与真实抖音数据严格区分，答辩中不宣称已接入内部接口。

### 8.5 第一版验收标准

1. 评委能在 3 分钟内连续完成选灵感、看空间、加约束和收方案。
2. 用户把预算从 500 元降至 300 元时，商品组合、总价、理由和校验结果同步变化。
3. “不能打孔”开启后，结果中不出现墙面钻孔或固定安装商品。
4. 每个结果都能解释使用了哪些空间、灵感和用户约束。
5. 效果图、商品清单和校验报告均明确区分事实、估算与演示数据。
6. 刷新后不恢复用户上传的本地房间图片；已保存方案可恢复。

### 8.6 当前实现

首版可操作 H5 位于 `ai-corner-renewal-mvp/`，采用无构建依赖的 HTML、CSS 和 JavaScript。当前实现使用预生成空间素材和结构化样例数据，后续可按 `extract_room_constraints → retrieve_products → generate_design_plan → validate_design_plan` 的顺序逐层替换为真实服务。
